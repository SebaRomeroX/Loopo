# CI tasks-validate red: seam generated by unreleased arggon main vs registry pin 0.5.0

## Context

Every `tasks-validate` run has been red since repo init — including the first
`push` run on `main` (`37137003602`, 2026-10-03 16:28), i.e. the failure
precedes any feature work; PR #1 merely inherits it.

Root cause (reproduced locally in a clean clone of `main`):

- The committed seam (`.agents/`, `.opencode/`, `AGENTS.md`,
  `.opencode/plugins/arggon/index.ts`, workflow template) was generated by a
  **git-install of ArggonManager `main` @ `8e3e9214`** — the `arggon` on PATH
  reports `0.5.0 (8e3e9214, main)`, 450 commits past the `v0.5.0` tag, but its
  `package.json` still says version `0.5.0` (unreleased dev state).
- CI installs the **registry release** `arggon-manager@0.5.0` (published
  2026-10-02, = tag `v0.5.0`) and runs `arggon init --no-commit`, which
  regenerates different bytes → drift gate sees dirty tree → red.
- Local reproduction: `arggon init --no-commit` with the git-main build on a
  clean clone → only `.convention.yml` timestamps (excluded from the gate) →
  would be green. With `npx arggon-manager@0.5.0` → 9 modified + 3 untracked
  (`.mcp.json`, `CLAUDE.md`, `.zcode-marketplace/`) → red, exactly as in CI.
- The workflow's **pinned-lag assertion cannot catch this**: it compares
  version *strings* (`0.5.0` vs `0.5.0`), so equal versions with different
  content slip through.

Remedy candidates (decision needed — spans ArggonManager's release process):

1. **Pin the workflow install to the seam's git commit** (e.g.
   `npm install -g "git+https://github.com/Arggon/ArggonManager.git#8e3e9214"`).
   Green immediately, generator byte-identical to the seam, keeps the newer
   local tooling. Deviates from the template's "install a release from the
   registry" design; the workflow file is excluded from the drift comparison,
   so the edit itself is stable. Revisit when a release contains `8e3e9214`.
2. **Regenerate the seam with registry `0.5.0` and commit** (the drift gate's
   own printed remedy). Green now, but downgrades the generated seam by 450
   commits of template changes and re-adds `.mcp.json`/`CLAUDE.md`/
   `.zcode-marketplace/`; the git-main `arggon` install would rewrite it back
   on the next local `init` → treadmill until a release lands.
3. **Cut a release of ArggonManager from current `main` (0.5.1), then re-pin**
   `ARGGON_VERSION`. The by-design fix ("A stale literal is a red test...
   the runbook's post-release re-pin"), but it is a cross-repo npm publish.

## Acceptance

- [ ] One remedy above is applied and `tasks-validate` is green on `main`.
- [ ] A subsequent PR run of `tasks-validate` is green (not only `push`).
- [ ] Local `arggon init --no-commit` with the developer's own `arggon` build
      leaves the tree clean (no flip-flop between generators).
- [ ] The chosen remedy is recorded here (or in an ADR) so the next release
      knows what to re-pin.
